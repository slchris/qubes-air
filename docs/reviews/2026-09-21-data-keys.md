# 2026-09-21 数据密钥迁移记录

范围：DATA-01 的密钥来源与迁移部分；基于已分组提交的 `main`（`bae7180`）继续工作。
未 push、未部署，没有操作真实基础设施。本文是工作区证据，不表示已发布构建通过相同验收。

## 行为变化

- DEK 成为唯一解锁路径：`DataKeyManager.KeyFor` 只返回 Qube 自己的随机密钥，没有时报告
  “不存在”，不再静默派生 master 密钥；master 读取只读，不再有任何创建路径。
- 旧盘首次解锁时迁移：Console 用已有 `qubes-air-luks-master` 派生旧键，把容器经
  `luksChangeKey` 原子换到库中 DEK；失败退回 add→验证新键→remove，任何失败路径都保留旧键。
- 新增 agent 服务 `qubesair.RekeyData`：拒绝非 LUKS、缺盘、两键皆不可用的请求；幂等；
  旧 keyslot 未移除时上报 `old_key_removed:false`。密钥只经 stdin 与进程替换传递，
  不进入 argv、不写盘，特权部分同样经 systemd-run。
- 迁移标记 `qubes-air-luks-legacy-slot-<id>` 持久记录“旧槽可能仍在”；每次解锁重试删除，
  删除经旧键失效验证后才清除；purge 同时删除 DEK 与标记。
- 接入 `agentunlock`：只有 agent 明确报告 `wrong_key` 才迁移；其它拒绝（无盘、非 LUKS、
  mount 失败）原样上报，不会被 rekey 掩盖。

## 验证

- `go test ./internal/service ./internal/agent ./internal/pki`：通过。
- RekeyData shell 测试（stub cryptsetup 与 systemd-run）覆盖：正常迁移、已迁移幂等、
  遗留旧槽删除、两键皆不可用、非 LUKS、缺盘、change 失败回退 add、remove 失败保留标记，
  以及空/非 JSON/类型错误/缺字段/非法 key/同 key/超量请求的拒绝。
- `agentunlock` 单测覆盖：有 DEK 直接解锁且不读 master、无 DEK 时铸键并迁移、旧键失效时
  用同一 DEK 重试、非 wrong_key 不触发 rekey、pending 时补删旧槽、remove 失败保留标记、
  master 缺失时报错且不铸新键。
- `datakey` 单测覆盖：无兜底、shred 删除 DEK 与标记、master 只读、标记幂等。
- ShellCheck 通过新脚本；`make pre-commit` 与 `make audit` 通过（见“门禁结论”）。
