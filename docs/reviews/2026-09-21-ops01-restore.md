# 2026-09-21 本地隔离恢复演练（OPS-01 预演）

范围：用真实 `qubes-air-backup` 与真实 Console 代码在**同一台 macOS 开发机**上完成
“备份 → 隔离路径恢复 → 重启 Console → 校验状态”的闭环。这是 OPS-01 的本地预演，
**不是离机恢复，也不是真机记录**：没有第二台机器、没有 Proxmox、没有真实 keyring。
正式 OPS-01 验收仍需在真实环境重做并记录 RTO。

## 环境与数据

- 主机：macOS arm64，Go 1.26.8；Console `0.1.0`，build `dev`。
- 源库：用当前代码的 `database` + `credential`/`zone` repository 新建的 schema 2 数据库，
  再补充代表性记录：1 个 provider 凭据（secret 仅为演练值）、1 个 Proxmox Zone、
  2 条 `agent_certs`（1 条有效、1 条已撤销）、1 条 `protected=1` 的 `qube_infra`。
- CA：通过真实 `CertIssuer.CA` 在源库中创建，并用真实 `RevokeFor` 触发撤销列表签发。
- 归档：`ops01-final.qab`，114,853 字节，header
  `{"format_version":1,"schema_version":2,...}`，口令经 `QUBES_AIR_BACKUP_PASSPHRASE`
  传入（演练用一次性口令，未落盘）。

## 步骤与结果

| 检查 | 命令/方法 | 结果 |
|---|---|---|
| 备份 | `qubes-air-backup create -db … -out …` | 成功，约 1 秒，归档 0600 |
| 错误口令恢复 | 用不同口令 restore | 拒绝：`wrong passphrase or corrupted archive`，退出 1，未创建目标 |
| 覆盖保护 | 对已存在库 restore，不带 `-force` | 拒绝：`restore target exists (use force to overwrite)`，退出 1 |
| 隔离恢复 | restore 到空目录新文件 | 成功，≤1 秒；同目录无 `-wal`/`-shm`；`PRAGMA integrity_check` = ok |
| schema 过新 | 复制库设 `user_version=99` 后备份并恢复 | 拒绝：`schema is newer than this console supports: archive schema 99, this console supports 2`，未创建目标 |
| 记录一致性 | 恢复后计数对比 | zones 1、credentials 3、agent_certs 2、revoked 1、qube_infra 1（protected 保留） |
| 凭据可解密 | 用原 keyring 打开恢复库并读取每个 secret | 成功：CA key 227 B、CA cert 627 B、provider secret 22 B |
| keyring 缺失/错误 | 用不同 keyring 打开恢复库 | 解密失败：`cipher: message authentication failed` |
| Console 启动 | 用恢复库启动 Console | `/health` 立即 healthy；`/api/v1/credentials` 与 `/api/v1/zones` 返回恢复的数据 |
| 吊销状态 | `GET /pki/revocations` | 200，签名 72 字节，payload 含已撤销指纹，有效期 5 分钟 |
| CA 缺失时 | 无 CA 的库上请求同一接口 | 503，不返回空列表（fail closed） |

本地 RTO（数据量 ~115 KB，同机同文件系统）：备份约 1 秒 + 恢复 ≤1 秒 + Console 到
healthy ≤1 秒。此数字只说明工具链可闭环，不代表生产库、离机拷贝或人工确认所需时间。

## 复现入口

```bash
go build -o /tmp/ops01/bin/qubes-air-console ./console/backend/cmd/server
go build -o /tmp/ops01/bin/qubes-air-backup  ./console/backend/cmd/qubes-air-backup

export QUBES_AIR_BACKUP_PASSPHRASE='…'   # 只从环境变量读
/tmp/ops01/bin/qubes-air-backup create  -db /path/qubes-air.db -out /path/backup.qab
/tmp/ops01/bin/qubes-air-backup restore -db /isolated/qubes-air.db -in /path/backup.qab -force

QUBES_AIR_ENCRYPTION_KEYS='v1:…' QUBES_AIR_API_TOKEN='…' \
  /tmp/ops01/bin/qubes-air-console            # 在恢复库目录启动，校验 /health 与 /pki/revocations
```

## 未覆盖（正式 OPS-01 必须补）

- **离机**：归档未经网络/介质传到另一台机器；只验证了单机隔离路径。
- **真实 keyring**：演练 key 在环境变量中一次性生成，未验证真实部署的密钥保管与轮换。
- **provider 对账**：未连接 Proxmox，未验证恢复后 qube_infra 与真实资源的对账。
- **agent 信任**：未连接真实 agent；撤销列表为合成指纹，未验证真实证书链与 bootstrap。
- **数据量与时长**：源库仅约 115 KB，RTO 不能外推到生产规模。
- **CA 灾难恢复**：演练 CA 是临时生成的，不覆盖真实 CA 泄露/重建与旧证书吊销一致性。

正式验收仍需：在 console qube 或独立环境按本记录步骤重做，绑定提交与构建版本，
记录实际 RTO、人工步骤和失败重试，并检查恢复后的 provider 资源与 agent 可达性。
