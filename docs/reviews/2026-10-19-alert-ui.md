# 2026-10-19 告警确认与历史视图

基线：`origin/main` `0e473ea`（分支基于该提交；#68 job 日志保留另经 PR #68 合入，与本改动
无文件重叠）。本阶段接上 G-E2 中"前端告警确认/历史视图未接"的缺口。

## 行为变化

- Monitoring 视图的 Active Alerts 现在显示每条告警的确认状态：
  - 未确认时显示 `Acknowledge` 按钮；请求进行中按钮禁用，避免双击写入两次；
  - 确认后显示操作者与确认时间，不再显示按钮；
  - 确认失败时在原位置显示服务端错误，按钮保持可用。
- 新增 Alert history 区块，从 `GET /api/v1/monitoring/alerts/history` 读取持久化的
  raised/resolved 转换，默认每页 10 条；`total` 大于已加载条数时显示
  `Show older (N more)`，按 offset 追加下一页。
- 历史不可用（503、网络错误）时明确显示"Alert history is unavailable (原因)"，不把空列表
  显示成"没有告警"。刷新按钮与 60 秒轮询一并刷新告警与历史。
- API 客户端新增 `acknowledgeAlert(id)` 与 `listAlertHistory(limit, offset)`；确认走服务端
  已有的 `POST /monitoring/alerts/:id/acknowledge`，不在前端本地伪造确认状态。

## 信任边界与失败路径

- 确认是操作者动作：服务端要求已认证 subject，并拒绝当前快照中不存在的告警。前端不改变
  这两条规则；认证关闭的开发控制台会收到 401 并显示服务端错误。
- 告警 id 在拼入 URL 前经过 `encodeURIComponent`；服务端仍执行长度与 `:` 结构校验。
- 历史分页参数由服务端校验（limit 1–100、offset 0–10000），前端只传固定页大小与累计 offset。
- 测试覆盖：确认调用参数、确认后显示操作者、确认失败保持可操作并显示原因、历史渲染、
  追加分页的 offset、历史 503 时显示不可用而不是空列表。所有新增前端测试通过 mock API
  边界驱动，不依赖真实后端。
