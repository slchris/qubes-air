# 2026-09-20 P0 安全加固记录

范围：ENG-01 的工具链准备，以及 SEC-01、SEC-02、SEC-03 的实现和自动化验收。
基于本地 `main` 的 `3b573c0` 及已有大量未提交改动继续工作；本轮没有 commit、push、发布或
真实基础设施操作。下面是工作区证据，不是某个已发布构建的证明。

## 行为变化

- 实际 agent 强制客户端角色检查与 CA 签名撤销状态；握手/恢复会话和长连接复查生效。
  新增公共只读 `/pki/revocations`，失败拒绝授权；不在读取时创建 CA。
- Exec 从 shell 文本改为有界 JSON argv，直接执行允许程序；FileCopy 使用目录描述符限制路径，
  两者继承 agent 沙箱。取消现在返回可识别的 context 错误。
- Proxmox 执行与调度共用强制验证的 HTTPS 客户端；SSH 使用已核验 known_hosts，握手可取消。

信任边界、失败方式、协议上限和升级配置见[安全控制](../security-controls.md)。
尤其需要更新 agent 的撤销状态地址、私有 Proxmox CA、SSH known_hosts 和 Exec 调用格式；
agent 包与测试环境新增 Python 3 依赖。没有自动更新外部 qubes-salt-config。

## 验证过程与结果

工具链使用本机已有 Go 1.26.8、golangci-lint 2.12.2、govulncheck 1.1.4，补齐 PATH 入口；
Makefile 增加 Python 3 检查，开发容器加入 Python 3。没有放宽扫描阈值或忽略失败。

实现前的完整 `make pre-commit` 基线通过。新增回归曾复现明文 Proxmox endpoint 被接受、
调用取消返回成功，以及空闲 gRPC 连接吊销后仍不退出；修复后通过。
服务脚本测试先遇到源码文件未设置执行权限，改为模拟打包安装到测试目录后运行；
该首次失败不作为旧 shell 绕过漏洞的复现证据。

本轮完整 `make pre-commit` 和 `make audit` 均已通过。首次 audit 被两处已有 ShellCheck
问题阻断：未使用变量和未引用的路径；做最小修复后全量重跑通过。随后补充输入输出上限、
超时及撤销状态并发测试，agent race 测试通过；最终再次执行 `make pre-commit` 和
`make audit`，两者均退出 0，100 个本地 Markdown 链接目标检查通过。

验收包含：

- Go 全量 race/coverage；角色、CA、用途、目标名称、有效期、恢复会话和长连接负向测试；
- 签名篡改、过期/回退、状态源失败、重启失败、重定向和并发读取测试；
- Exec 字面参数、拒绝 shell 文本、输入输出限额、取消、超时、退出码；
  FileCopy 越界、符号链接、非法头、超量文件与失败后保留原文件；
- 全量 lint/gosec/复杂度检查、govulncheck、ShellCheck、本地 Markdown 链接及 CI 门禁检查；
- 前端 check 零错误/警告、build、Vitest 5/5、npm audit 零漏洞。

govulncheck 未发现代码可达漏洞，但报告依赖模块存在 1 项当前不可达漏洞；不能描述为
所有依赖完全没有漏洞。原始本机日志位于 `/tmp/qubes-air-p0/`，属于临时验收产物，不纳入仓库；
可复现入口为仓库根目录 `make pre-commit` 和 `make audit`。
