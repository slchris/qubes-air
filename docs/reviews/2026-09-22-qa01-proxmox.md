## 第一轮（修复前 `efb513e8`）：暴露问题

- provision：job succeeded；agent healthy；suspend/resume 均 succeeded（IP .124 → .125）。
- release：job **failed** —— `remove RemoteVM: deregister [...]: qrexec call failed: exit status 126,
  stderr: Request refused`，Qube 落到 error。
- 诊断：dom0 的 `mgmt.remotevm.register` state 未应用（补应用 `changed=2`）；补后仍失败，
  因为 console 传的是裸 Qube 名，而 dom0 服务把所有可操作对象限定为 `remote-*`。注册是
  quiet 失败，所以问题到 release 才显形。修复 `1dbc87f` 后，卡住的 Qube 重试 purge 成功。
- 工具观察：`GET /api/v1/qubes` 经 `qubes.ConnectTCP+8080` 代理返回 500/截断；经 LAN HTTP
  正常 200。属于本地代理通道限制，不是 console 缺陷；后续 QA 走 LAN 接口。
